# NostalgicVerse — Phase 11 Social Architecture Rebuild

## Executive Summary
Phase 11 implements a complete, authoritative overhaul of the NostalgicVerse social and community ecosystem. Prior to this phase, multiple architectural flaws led to chat message duplication (2–3x for sender), disappeared chat composers, passive friend notifications, and decoupled museum exhibits.

This rebuild establishes a strict, database-first architecture where:
1. **The SQLite Database is the Single Source of Truth**: No client state or `localStorage` acts as authority for social data.
2. **WebSocket is Purely Realtime Transport**: Realtime events notify active clients of state changes but never supersede canonical database writes.
3. **HTTP REST is Authoritative History & Mutation**: All writes pass through transactional REST APIs that enforce authentication, authorization, and idempotency before emitting realtime events.
4. **Idempotent Reconciliation**: Every client mutation generates a deterministic `client_message_id` or unique key that reconciles optimistic bubbles with server-committed records.

## High-Level Architecture & End-to-End Data Flow

```
[ User Interaction ]
         │
         ▼
[ Client Application (Browser) ]
    ├─ Optimistic UI Update (Tagged with client_message_id / pending state)
    └─ Authenticated REST API Request (Cookie-based session)
         │
         ▼
[ Express API Gateway (`server/index.cjs`) ]
    ├─ `authMiddleware` (Session extraction from cookie / Bearer)
    ├─ `requireAuth` (Strict 401 JSON for unauthenticated API requests)
    └─ Route Handlers (`server/api/chat.cjs`, `social.cjs`, `community.cjs`)
         │
         ▼
[ Authoritative SQLite Database (`data/nostalgicverse.db`) ]
    ├─ Foreign Keys Enforced (`PRAGMA foreign_keys = ON`)
    ├─ WAL Journaling (`PRAGMA journal_mode = WAL`)
    ├─ ACID Transaction Commit
    └─ Generates Canonical Server ID & Timestamp
         │
         ▼
[ Realtime Broadcast Hub (`server/realtime/websocket.cjs`) ]
    ├─ Emits Standardized Event (`message.created`, `friend_request.created`, etc.)
    ├─ Emits Envelope with Unique `event_id` and Canonical Entity
    └─ Emits with `excludeWs` or client deduplication support
         │
         ▼
[ Realtime Client Singleton (`assets/js/realtime-client.js`) ]
    ├─ Manages Exactly ONE WebSocket Connection per Tab
    ├─ Filters Duplicate Frames via `seenEventIds` Set (TTL 60s)
    └─ Dispatches Event to Subscribed UI Handlers
         │
         ▼
[ Client UI Reconciler (`chat-ui.js`, `friends-ui.js`, `content-interactions.js`) ]
    ├─ Matches `data-id` or `data-client-id` in DOM
    ├─ Reconciles Optimistic Bubble in Place
    └─ Guarantees EXACTLY ONE DOM Element Rendered
```

## State Synchronization Principles

1. **Zero Browser Authority**: All friends, requests, unread counts, messages, and comments are fetched from the server. `localStorage` is never queried or trusted for server state.
2. **Deterministic Ordering**: Timestamps and canonical IDs generated by the server establish the immutable timeline of events.
3. **Idempotent Retries**: Network drops or duplicate button clicks replay existing canonical records rather than generating secondary rows.
4. **Resilient Reconnection**: Re-establishing a lost WebSocket connection triggers a shallow cursor sync to fill gaps rather than destroying and rebuilding the DOM.
